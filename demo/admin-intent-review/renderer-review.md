# Inline/result component review

Baseline `5a8ba08`. All 37 built-in result components were captured. Thirty-six use the current built-in sample; `capabilities` has no built-in sample and was captured from the actual local tool registry. These are first-visible viewport observations, not a test of every interaction or possible result. Sandbox boundaries, exact revisions, read-only snapshots and prepared follow-up actions must remain.

The source snapshots are intentionally independent of the live application. Do not add live execution to a saved result just to make it feel interactive. Offer a named link to inspect or prepare a follow-up under the viewer's own access.

## Shared result contract

Use one compact result header: **question/title, source/environment, observation time, evidence type, completeness, verdict**. A saved result is read-only. A named prepared action opens editable arguments under the current viewer's access. Successful transient outputs start collapsed in chat; failures, partial data and unresolved assumptions remain visible. Complete evidence, CSV/JSON/TSV, raw logs and format-specific export live in a consistent secondary menu where they are not the primary job. Keep direct export where reproduction is the main job.

No renderer interaction, large-graph performance, dark mode or responsive behavior is certified by these viewport captures. The dedicated state ledger covers Admin transitions separately.
