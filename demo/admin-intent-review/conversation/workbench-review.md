## Concrete material findings

1. **P1 — The production investigation stops before the source workbench.** `web/views/semantic-path-trace.html:56` constructs `DTPath.Browser` without `onSource`; `web/views/_path-browser.js:62` consequently renders no **Open source** action. The production capture shows a source locator and expandable JSON, while the synthetic conversation alone implements snapshot → workspace copy → edit → save. The real `/editor` is also a separate surface, not the conversation-first task workspace. **Required correction:** wire retained source identity and exact range to a read-only source peek and an explicit writable-workspace action in the production task flow; preserve the focused path and return state. A prepared `code_read` using the retained `revisionKey` and exact file/from/to can safely recover immutable source access, provided the preparation is explicit and unresolved library identity disables the action. A current-branch/editor URL cannot substitute for that snapshot. Until task/workspace continuity also exists, present this delivery as production editor/path components plus a synthetic conversation, not completion of the production investigation workflow.

2. **P1 — The path adapter can replace an object's own provenance with its parent's.** In `web/views/_path-browser.js:16`, `...metadata` follows `...n`. The production caller at `web/views/semantic-path-trace.html:56` supplies parent `repo`, `revision` and `evidence`, overriding any retained values on the selected node. A read-only model reproduction changed `LIB/handler @ library-sha` into `APP/person @ app-sha`. The supplied production fixture uses one repository and cannot expose this. **Required correction:** use analysis metadata only as defaults; retain per-node repository/revision/evidence and explicit unknown identity. Add a cross-source fixture that verifies the selected node, source peek and workspace handoff all display the same admitted identity.

3. **P2 — Search finds paths but does not visibly disambiguate them, and active files cannot be revealed.** The API returns full paths, but `web/workbench-entry.js:145` renders only `row.name`; the full path is a hover title at line 140. Duplicate basenames therefore produce indistinguishable search rows. `setActive()` at line 150 only highlights already mounted rows; it does not expand ancestors, scroll to the file or supply the contracted **Reveal active file** action. Long package chains are neither compacted nor focusable as a local root; indentation merely caps at eight levels at line 142. **Required correction:** show relative path/workspace in search results, add reveal-and-focus for the active file, and implement compact folders or an accessible local-root/ancestry alternative. Verify repeated filenames and an unopened deep source path with mouse and keyboard.

4. **P2 — Back/Forward does not fully restore the operator's current navigation state.** `web/views/_path-browser.js:42` saves only scroll before travel, unlike `focus()` at line 38, which saves query and offset too. Reproduction: focus B → Back to A → change the search and result page → Forward → Back; A restores the old query/page. Route-item navigation at line 58 additionally carries `state.edge` from the former selected node into an ancestor selection, so **Selected connection** may describe the wrong step, and that path bypasses the normal 200-entry history cap. **Required correction:** centralize state capture/navigation, retain the correct edge per route step, truncate forward history consistently and enforce the history limit for every navigation action. Verify route clicks and query changes after Back, not only the first search → result → Back case.

5. **P2 — The neighbor lists are progressively accumulated, rather than bounded slices.** `web/views/_path-browser.js:68–69` appends 25 more rows each time without removing earlier rows. A 500-way fan-out can therefore mount all 500 relationships. Node search at lines 9–12 does not index edge labels or call-site identity, so finding a specific relationship among repeated caller/callee targets still requires sequential inspection. This falls short of the contract's caller/call-site retrieval behavior and the documented “25 … neighbors at a time” bound. **Required correction:** paginate or virtualize each relationship list and provide relationship/call-site filtering with counts; preserve the chosen edge while navigating. Verify a late call site among repeated targets, not just a unique node named `Method 49999`.

Inspected the actual shared editor/tree/path implementation, production editor and semantic renderer, conversation adapter/styles, verifier and relevant model/backend tests. Used small read-only Node reproductions for the Back/Forward query loss and metadata overwrite. No production code was modified by this review.

The parent reports the build and 56 focused tests passing. I did not rerun those tests, and their count is not a UX verdict. The manifest records fifteen browser check groups, viewport/document widths and total DOM nodes. It does **not** record response bytes, lookup duration, first useful paint, heap or active-model pressure, and the 50,000-node conversation model is constructed in full in the browser (`demo/admin-intent-review/conversation/workbench.cjs:6–29`). Bounded mounted detail therefore does not prove bounded fetching or memory. The deep-path verifier clicks through generated controls programmatically; it proves reachability and width, not the usability of 200 manual steps.

Independent live browser replay was unavailable: the browser tool reported no available browsers. No additional server was started. The supplied captures and source were the visual/functional evidence. The deterministic detector was unavailable after the parent's launcher download-verification failure; it was not bypassed or represented as clean. The extra language tokenizers added after capture do not change the inspected layout, but those languages' highlighting is not visually verified here. No live Joern analysis, Java service regression, durable team-sharing service, screen-reader session or physical phone test is implied.
